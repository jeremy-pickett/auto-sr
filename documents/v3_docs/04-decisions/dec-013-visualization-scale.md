# DEC-13 — What must we keep so the pictures never need a re-run?

*Formal name: visualization scale. Cite this record as **DEC-13**.*

**Status:** open · **Who decides:** the project owner, on a proposal · **Kind:** deferred detail with a deadline — it must land before storage formats set

> **In one sentence:** the ambitious future views — 3D worlds, time as a walkable dimension, many-experiment comparisons — must be drawn from stored evidence, never by re-running experiments; that means today's storage decisions quietly decide which future pictures are affordable.

---

## What this is about

A core rule of this platform: playback is reading a finished record, never re-simulating. Step backward, jump around, apply a view invented years later — all of it works because the history is complete and on file.

The planned advanced views raise the stakes on that rule. A three-dimensional world you can fly through, time rendered as a solid shape you can walk around, a whole Study's worth of experiments compared in one scene — each is only honest (and only affordable) if it can be built *from what was stored*. If a view needs the experiment re-run server-side every time someone opens it, the view is producing new evidence and calling it a display — and it will be too expensive to offer anyway.

So the real question is a storage question wearing a graphics costume:

> **What forms of stored evidence do the future views need — and are we recording them now?**

Records are written once and read forever. A picture format we fail to plan for now is a picture that will someday require re-running ten thousand experiments to draw.

## What this is blocking right now

- Nothing visible — today's views run happily on today's storage.
- The deadline is real but not dated: this must be answered **before** the large-scale storage format is frozen, which makes it a companion to DEC-2 and DEC-8 rather than an independent timeline.
